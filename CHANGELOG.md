# Changelog

All notable changes to this project are documented in this file. The format follows the spirit of Keep a Changelog, and the project uses semantic-ish versioning while it is pre-1.0.

## [0.1.1] - 待发布

### 跨模型兼容与诊断隐私

- 新增按实际转发目标判定的兼容策略：`outputTokenReplay`、`requestCompression` 和精确的 `opaqueTaskModels`；模型叫 `gpt-*` 不再自动证明自定义上游支持原生扩展。
- `stripAlways=true` 默认覆盖所有父模型；只过滤顶层 `include` 的 `output.encrypted_content`，保留历史输出密文、推理密文与原生压缩密文。
- 修复仅选择器变化仍发送旧正文的问题；外部路由自动转发无压缩 UTF-8 请求，改写正文始终移除失效编码声明。无效 JSON、非法 UTF-8、解压失败返回 400，接收正文或解压结果超限返回 413。
- 经 CC Switch 保留其摘要封装，绕过 CC Switch 时仅严格还原 `ccswitch-compaction-v1:` 文本摘要为普通 user 消息；损坏或未知版本明确拒绝。
- 兼容配置 CLI 支持 JSON 字符串数组，修改 `compat.*` 不再同步无关模型目录。默认日志只记录计数及安全异常类型，不记录参数修复裸词。
- 诊断包先结构化脱敏再序列化，覆盖 URL 凭据、Bearer、Fernet 和摘要；损坏 JSONL 行明确省略，仍要求分享前人工检查。
- 新增真实 HTTP 边界、诊断包和子代理证据负向测试；在线回归要求显式 `CODEX_BIN`、临时 home、独立子会话、正确模型、真实回答、派发与成功等待证据，不能靠父代理复述口令通过。派发诊断保留口令命中及任务指纹，不记录任务正文；首轮失败与独立复核分开保留，不承诺每轮模型编排稳定。

### 文档与发布交接

- 同步两份 README、架构、兼容性、隐私、安全、贡献及发布说明：补充策略精确语义、配置生效时机、诊断和严格在线回归，修正版本及 CI 范围。
- 0.1.0 已发布；0.1.1 为源码候选，不能用 Git 推送或打标签代替 npm 发布。macOS 仅配置手动 CI，本次未运行；gitleaks 被跳过时不算扫描通过。

> 以下为 0.1.0 的历史开发记录，不代表所有描述仍是现行行为。例如参数修复曾记录裸词；0.1.1 起只记录工具名及数量，历史原始日志不会自动改写，分享诊断前仍须人工检查。

## [0.1.0] - 2026-10-08

Initial version.

### Added

- Local compatibility layer that sits between the Codex client and an upstream endpoint (a local CC Switch proxy by default, or a custom OpenAI-compatible endpoint), listening on `127.0.0.1:15731` by default and forwarding to `127.0.0.1:15721` by default.
- Stage A: strips the `encrypted: true` marker from the `message` property of the collaboration tools (`spawn_agent`, `send_message`, `followup_task`) so an official parent request produces plaintext arguments instead of ciphertext.
- Stage B: projects plaintext out of `encrypted_content` containers into standard `role: "user"` messages, for official and third-party downstreams alike.
- Stage C: explicit HTTP 400 (`compat_layer_reject`) when real ciphertext would have to be delivered to a third-party child, instead of silently handing over an empty task.
- Input normalization for orphan tool outputs: delegation blocks without a matching `function_call` become ordinary user messages, so chat-protocol gateways stop rejecting the whole request with HTTP 400. Empty orphan outputs are dropped; paired tool outputs pass through untouched.
- CLI with `install`, `repair`, `start`, `pause`, `stop`, `restart`, `status`, `doctor`, `logs`, `config`, `bypass`, `restore`, `uninstall`, `selftest`, `version`, and `help`, plus the global flags `--json`, `--dry-run`, `--yes`, `--verbose`, `--port`, `--upstream`, `--home`, `--reclaim`, and `--allow-remote-upstream`.
- Three-level interactive menu whose labels follow the system locale (English or Chinese, overridable with `CODEX_COMPAT_LANG`): status, start/resume, pause, restart, install/repair, and more; the install entry is pinned first when the tool is not installed yet. The "more" level covers logs, health check and repair, common settings, CC Switch integration, models and prompts, emergency bypass, diagnostic bundle, configuration restore, and uninstall.
- Persistent configuration at `~/.codex-compat/config.json` (overridable with `CODEX_COMPAT_HOME` or `--home`), with command-line > environment > file > default precedence.
- Installation safety: prerequisite checks, port selection with automatic fallback (`15732`–`15831`) and reuse of an existing instance, backups before every write, and an install manifest (`~/.codex-compat/install-manifest.json`) that makes `restore` and `uninstall` precise.
- Explicit Multi-Agent V2 configuration during install (`tool_namespace = "agents"` plus an explicit enable), so the effective subagent surface no longer depends on implicit fallbacks.
- DeepSeek model template and subagent roles kept in sync idempotently, driven by `config/mappings.toml` and the templates under `config/templates/`; conflicting configuration is reported rather than overwritten.
- Fused DeepSeek prompt template (`config/prompts/deepseek-codex.md`) addressing DeepSeek subagents that stop early or run empty, derived in part from the DeepSeek Codex integration guidance and constraints authored by 程小帮. Both sources are credited.
- Crash supervision: a guard process restarts the layer with exponential backoff (2 s up to 60 s), treats 30 s of uptime as healthy, and gives up after 10 fast failures instead of looping forever.
- Request-body protections: 64 MB body cap, `zstd`/`gzip`/`deflate` decoding, `content-encoding` removal after a rewrite, and `content-length` recomputation.
- Counter-based logging with size-capped rolling files, plus an opt-in diagnostic trace that is off by default and capped in size when enabled.
- CC Switch detection for takeover state, and the reclaim policy (`auto`, `notify-only`, `off`) for when CC Switch stops routing Codex through its local proxy. Automatic reclaim is throttled (at most one attempt per 30 seconds and 20 per hour, then it only notifies) so a config fight cannot loop forever.
- Platform adapters: Windows scheduled task and balloon notification, macOS launchd agent and `osascript` notification, Linux systemd user unit and `notify-send`/`zenity` notification.
- Offline test suite covering the rewrite rules, configuration handling, installation safety, tracing, and the compatibility input normalization, plus opt-in live cross-provider checks.
- MIT license, privacy and security policies, third-party notices, and compatibility documentation.

### Added during pre-release review

- Instance isolation fixes found by a fresh-user audit: a non-default `CODEX_COMPAT_HOME` no longer derives the main instance's service/guard names (`platform.instanceNameOf` now returns `path-<dir>-<hash>` for custom homes, and only the default home maps to `main`), so running `uninstall`/`stop` from a temporary or lab home can no longer delete the real main instance's scheduled tasks. `status`, `doctor` and `start` now verify the health endpoint's `home` before calling a port "healthy" or "started", and `pause` reports a port owned by another instance instead of calling it a leftover.
- `--catalog-mode auto` no longer produces an instance with neither `model_instructions_file` nor `model_catalog_url` (the branch was unreachable): `auto` now resolves to `instructions` with an explicit notice, and the four mode values are named constants.
- The interactive menu states that provider-level catalog hosting is not supported by Codex today: selecting it prints the measured evidence (0.160.1 never fetches `model_catalog_url`; `api_key_model_discovery` is still under development) and requires explicit confirmation before enabling.
- `codex-compat help` now lists `instance`/`lab` (with its flags), `bundle` and `diagnose`.
- New onboarding test (`npm run test:onboarding`) walks the fresh-user path end to end: help inventory, fresh-home `status`/`doctor`, menu rendering and exit, the lab-instance lifecycle, idempotent uninstall, and the guarantee that a custom home never touches the main instance's tasks or borrows its health status.
- Three defects found by the 2026-10-10 A/B experiment are fixed: a lab instance's watchdog now syncs model mappings into the instance's own `CODEX_HOME` instead of the host's `~/.codex` (`instanceCodexHome()` resolves the target from the instance metadata, so creating or starting a lab instance can no longer rewrite the main environment's model catalog); the generated lab `config.toml` now declares the Windows native sandbox (`[windows] sandbox`, copied from the host configuration and falling back to the documented `unelevated` mode) because without it shell commands inside a lab instance are rejected by policy; and `instance run` now sends an argument containing newlines through the child's stdin instead of the Windows command line, which truncated multi-line prompts to their first line.
- Prompt hardening for gateway models: the fused DeepSeek template now requires tool call `arguments` to be strictly valid JSON with quoted string values (`"fork_turns": "none"`, never a bare `fork_turns: none`), and states the consequence — a call whose arguments do not parse never runs yet stays in the conversation, so every later request in that conversation is rejected. Added after the 2026-10-14 incident in which a gateway model wrote `fork_turns: none`, Codex kept the unparsable call in the thread history, and the gateway then answered `HTTP 400 input[763].arguments ... invalid character 'o' in literal null (expecting 'u')` on every following turn; retrying could not recover that conversation, and upgrading CC Switch could not either.
- Diagnostic trace now finds the model instructions wherever Codex puts them. Codex 0.162.1 sends no top-level `instructions` field at all: a captured real request carries the base instructions as the first `role: "developer"` message inside `input` (byte-identical to the catalogue template), while the catalogue value itself arrives as a `{ text, provenance }` object in the session record. The previous string-only check silently reported `instructionsBytes: 0`, `hasInstructionPriority: false` and stored no body — so the one diagnostic meant to answer "did the prompt reach the model?" answered "no" on a machine where the prompt was delivered correctly. The trace now resolves the text from either location and records `instructionsSource` (`instructions` / `developer-message` / `none`), normalises `{ text }` and content-part shapes, and so produces an `instructionsHash` that can again be compared against the template character for character. Both shapes are covered by `npm run test:trace`.
- Template sync is now a managed step instead of a one-shot copy. `seed()` only ever copied the packaged `prompts/` and `templates/` into the runtime home on first install and nothing compared the two afterwards, so a template improved in the package could never reach the copy that `mappings.apply` actually reads. Measured on 2026-10-14: the deployed copy was 501 bytes behind and missed two clauses, while `doctor` reported no pending mapping work the whole time — the mapping check compares the catalogue against that same stale copy, so all three layers agreed everything was fine. The tool now records an ownership hash per managed file (`state/templates.json`), compares it during `install`/`repair`, at watchdog startup and in the same 30 s loop, and refreshes only files that still match what it wrote; a file the user edited is reported and never auto-overwritten, so `auto` cannot trade silent staleness for silent data loss. Policy `service.templateRefresh` (`auto` / `notify-only` / `off`, default `auto`) mirrors the reclaim policy by sharing its three-value shape and throttle; `codex-compat templates [--force] [--dry-run]` and the menu's "Refresh templates & prompts (hop 1)" are the manual entries, and `install`/`repair --refresh-templates` folds the same refresh into an install. Every refresh is backed up under `backups/templates/<changeId>/` with a transaction journal, the tool never deletes a file the package does not ship, and `mappings.toml` is excluded because the menu switches own it. `doctor` gained a `templates` line, files with no record yet are adopted when they already match the package and reported otherwise, and the whole migration path never silently overwrites anything. Covered by `npm run test:templates` (state decisions, all three policies, `--force`, backups, user-file and symlink safety) plus the existing offline suite.
- `instance update [<name>]` (alias `lab update`) manually refreshes a lab instance's prompt copy from the package, with no name meaning every instance. Lab instances receive their instructions through a top-level `model_instructions_file` pointing at `<instance>/prompts/deepseek-codex.md`, so the package template never reaches them after `instance create` — measured on 2026-10-14, both instances on this machine still carried the 2026-10-09 revision (23,499 characters) and were missing both the two previously added clauses and the whole strict-JSON section. The command reports per instance (`已是最新` / old → new length / `catalogMode=…` when the instance has no prompt file), backs the previous copy up under the instance's own `compat/backups/`, honours `--dry-run`, and prints the reminder that an already-open Codex session inside the instance needs a new turn to pick the new prompt up. Covered by a case in `npm run test:instances`.
- Invalid tool `arguments` are now repaired before forwarding. The same failure struck a second time on 2026-10-16 (the 2026-10-14 incident again, in the same long-running thread): a gateway model wrote `"fork_turns": none`, Codex stored the unparsable call in the history, and the gateway rejected every following request with `HTTP 400 … input[572].arguments … invalid character 'o' in literal null (expecting 'u')`. The template hardening from 2026-10-14 was verifiably in place for that turn — package, runtime copy and catalogue entry all matched the same hash — so prompt-level mitigation lowers the odds without removing them, and the deferred layer-side safety net was added instead. `src/repair-args.cjs` quotes bare words in a value position, with a string-state-aware scanner so identical text inside a message body is untouched, and only adopts the result when it parses as JSON (anything else is forwarded unchanged, so no half-fixed body is ever sent). The proxy counts repairs as `argsRepaired` on the health endpoint and logs an `args_repaired` event with the tool name and the bare word only — never the argument body, keeping the no-task-bodies-in-logs rule. Covered by `npm run test:repair-args` (valid JSON untouched, nested and array values, string isolation, unrepairable input, real incident sample, input walk) and by a new end-to-end assertion in `npm run test:install-e2e` that the upstream receives repaired bytes while the message body keeps the original text.
- Mapping-drift guard: the watchdog now re-checks the model catalogue every 30 s with the side-effect-free `mappings.apply({dryRun:true})`, not only once at startup. CC Switch regenerates `~/.codex/cc-switch-model-catalog.json`; on 2026-10-12 11:27 it replaced the injected 24,000-character template in the managed DeepSeek entries with its own 117-character default, so prompt optimisation had been silently off for two days with nothing anywhere reporting it. Drift is handled by the same policy and throttle as the `base_url` reclaim (`service.reclaim`): `auto` rewrites the injection from the mappings and notifies, `notify-only` only notifies, `off` does nothing, and after 20 recoveries within an hour it notifies without rewriting. Its state is separate from the `base_url` drift state, so neither drift can consume the other's quota.


- Multi-instance (lab) management: `codex-compat instance create|list|status|start|stop|env|run|refresh-catalog|remove` (alias `lab`) creates self-contained instances under `~/.codex-compat/instances/<name>/`, each with its own `CODEX_HOME`, compatibility home and listen port (allocated from `15900`). Instances register no scheduled task unless `--autostart` is passed; `--key` keeps the plaintext key in the instance's `secrets.env` and is masked in every output, while `--key-env <VAR>` writes nothing to disk.
- Provider model catalog hosting: the layer serves `GET /__compat/catalog` and writes `model_providers.<id>.model_catalog_url` only when there is no global `model_catalog_json` and the upstream `/models` is not already a Codex-native catalog (no `model_messages` / `base_instructions`). A native upstream or a failed refresh keeps the existing value and reclaims a key the tool wrote earlier, instead of overwriting richer metadata with neutral placeholders. The key requires Codex ≥ 0.156; older versions use `model_instructions_file` in a single-provider lab home.
- Fuzzy model matching in `config/mappings.toml`: a binding can declare `model_id_like`, matched case-insensitively against the model id's last segment (for example `ccs-deepseek/deepseek-v4.1-flash` → `deepseek-v4.1-flash`). An exact `model_id` wins, zero matches raise `missing_model`, more than one match raises `ambiguous_model` and skips the binding, and each model is managed by exactly one binding. The shipped mappings now write both `model_id` and `model_id_like`.
- Official-only protection (`features.officialGuard`, on by default): prompt and catalog writes are refused for models named like an official one (`gpt-*`, `codex-*`, `o<N>`), a pure-official setup fails `install` with zero writes, zero processes and zero scheduled tasks, and `doctor` reports `official-untouched` and `provider-catalog`.
- Menu v2: eight main groups (status & doctor, start/pause/restart, install/repair, lab instances, feature switches, settings, tools, danger zone), a first-run wizard that creates a lab instance to try before attaching the main configuration, a single feature-switch panel (prompt optimization, subagent roles, provider catalog hosting, official guard, reclaim policy, bindings view, `verbose` default), and a settings panel for port, upstream, autostart, language and trace.
- New configuration keys: `features.providerCatalog` (default `false`), `features.officialGuard` (default `true`) and `runtime.verbose` (default `false`, the persistent default for `--verbose`, overridable for a single run with `--no-verbose`).
- Verified-baseline reporting: `src/codex-version.cjs` now exports `VERIFIED_BASELINE` (`0.160.1`, the Codex CLI version this tool is verified against, so an upgrade that breaks delegation can be pinned back), and `doctor` prints a `codex-version` line comparing the detected version with it — `Codex 0.160.1 (verified baseline)` when they match, otherwise `Codex <current> (verified baseline 0.160.1; roll back to this version if you hit problems)`, with the baseline appended when the version cannot be probed. The line is display-only and never fails the check.

### Fixed during pre-release review

- Port selection now honours an explicit `--port` before the port recorded in the install manifest, so a previous automatic fallback can no longer shadow the requested port. Candidate order is `preferred > recorded > scan 15732-15831`.
- Process discovery on Windows no longer double-escapes backslashes and runs PowerShell via `-EncodedCommand`, so `pause`/`stop` really terminate the watchdog and proxy processes instead of reporting success while leaving them alive. Process matching is additionally scoped by runtime home, so another checkout using the same source tree is left alone.
- Preflight refuses to treat an unrecognised listener inside the layer's port range as the upstream endpoint, which previously poisoned `originalBaseUrl` (for example `15732` instead of the CC Switch `15721`). A previous-generation layer port is still recognised when CC Switch is taking over, and the recorded original upstream is never overwritten by the current `base_url`.
- `install` clears the intentional-stop flag before registering services, so a previous `pause` can no longer make the watchdog exit immediately and fail the health check.
- `codex-compat config` no longer crashes on load (duplicate `config` identifier); the command is covered by a regression test.
- Windows scheduled tasks are namespaced as `CodexCompatService` / `CodexCompatServiceGuard` instead of the legacy `CodexCompatLayer` / `CodexCompatGuard`. `install` cleans up legacy-named tasks that point at the current runtime home, and `--cleanup-legacy` removes the rest.
- DeepSeek subagent roles now pin `model_reasoning_effort = "high"`; the redundant per-role copy of the 程小帮 guidance was removed because the fused model template already carries it.
- Diagnostic trace now resolves its directory from the runtime home and can be enabled through `runtime.trace`, instead of only through environment variables while writing inside the checkout.
- `--verbose` is now functional instead of a documented no-op: it prints resolved paths, port-scan attempts, raw CC Switch detection, mapping diagnostics, exception stack traces, and the recent system commands that were executed. Output without the flag is unchanged, and a regression test locks that in.

### Notes

- Windows is verified on real hardware, including install, restore, autostart, notifications, and the cross-provider delegation matrix. macOS and Linux are implemented and exercised by CI, but are marked experimental until they are verified on real hardware.
- This is an unofficial project and is not affiliated with OpenAI, DeepSeek, or CC Switch. It relies on undocumented Codex behaviour, so a Codex upgrade can break it; `codex-compat bypass` (emergency bypass) and `codex-compat restore` are the intended escape hatches.
- No telemetry. Normal logs record counters, model names, and event types only; task bodies and authentication headers are never written to disk.
- Provider model catalog hosting is implemented but disabled by default (`features.providerCatalog` defaults to `false`). Verified on Codex 0.160.1 (2026-10): Codex does not fetch a provider-level `model_catalog_url` for env_key providers (the layer sees no `/__compat/catalog` request and no model cache is refreshed), even though `model_catalog_url` is already a recognised provider key in that version — it sits alongside `base_url`, `env_key`, `env_key_instructions` and `experimental_bearer_token` and raises no unrecognized-setting warning. With a valid `model_catalog_url` configured for a lab instance (the layer really serves a 36 KB `/__compat/catalog`), `codex debug models` returns `{"models":[]}` and the layer records zero requests to that endpoint; `codex features list` reports `api_key_model_discovery` as `under development` (false) and `remote_models` as `removed`, which is also why adding `[features] api_key_model_discovery = true` or `remote_models = true` does not trigger model discovery. `model_instructions_file` is honoured only as a top-level key; placing it inside `[model_providers.<id>]` makes Codex ignore it (the lab scaffold was fixed accordingly), and with the top-level form the instructions traced by the layer match the repository template character for character (23,498 vs 23,499 characters, differing only by the trailing newline). In the CC Switch case the template is carried by a model catalog entry that already exists in the environment — the catalog CC Switch maintains (for example `~/.codex/cc-switch-model-catalog.json`), whose `ccs-deepseek/deepseek-v4.1-flash` and `ccs-deepseek/auto(free)` entries hold the repository template as `base_instructions` / `model_messages.instructions_template` (23,499 characters) — and a real main-instance `codex exec` session confirmed the client request body matched the template character for character; which configuration pointer hands that catalog to Codex is the top-level `model_catalog_json` key in `config.toml` (this machine: `model_catalog_json = "cc-switch-model-catalog.json"`, with no `model_instructions_file` present, so the catalogue entry is the only instructions source), and this layer only writes the template into the catalog entry — which is why a CC Switch regeneration of that file silently removed the template until the mapping-drift guard above was added. `~/.codex/models_cache.json` is a stale cache (a 2026-09-24 file whose DeepSeek entry carries only a 68-character template), not the effective source. The feature remains implemented so it can be re-enabled once Codex promotes provider-configured model discovery to stable (`api_key_model_discovery` moving from under development to stable); the blocker is that capability's status, not the build installed on this machine and not a missing fix in this tool.
